## Proposed changes to the procedure

Numbered, each with a recommendation. **None is applied.** The rulings are John's.

1. **Correct the count of upgrades at the top of the ladder to two**, in `docs/weekly-reading.md` ("thirty-five upgrades, three of them at the top... about thirty-two" should read "two of them at the top... 33 weekly"), and write the header comment of a reading record from the real count. *Recommend: yes. A plain correction; a small pull request.*
2. **Narrow `noted` to what happened in the window or was newly found**, and say in the procedure that an older item the entry already holds is `quiet`, with the fact in `found`. An older item the entry does *not* hold remains a `flagged` item (decision 11 already says so). *Recommend: yes. It keeps the public reading page honest about a quiet week. Alternative: keep `noted` as it is and add a visible "older" label on the page.*
3. **Require the run to open every record it cites for a `noted`, `stage-change` or `flagged` item, and to cite the maker's, regulator's or journal's own page where one exists**, listing in `sources` only pages it opened. Add one search per upgrade aimed at the register itself using the search tool's domain filter (for example the regulator's site, the trial registry, PubMed), since the tool cannot filter by date but can by site. *Recommend: yes for the opening rule. The domain-filter search is worth a trial reading before it becomes a rule; it costs about 33 more searches.*
4. **Make the export script stamp the Pacific date**, not the machine's, so a cloud run and a Mac run write the same thing. *Recommend: yes; it is a small change to `scripts/export.py` (four lines) and the same fix applies to any sibling that stamps its data by the machine's date.*
5. **Say in the procedure that a quiet verdict means "nothing turned up in the search results", and put the one-line caveat in the reading page's key**, so the report no longer needs a sentence after the list. *Recommend: yes.*
